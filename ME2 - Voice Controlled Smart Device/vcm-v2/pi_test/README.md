# pi_test — Raspberry Pi voice command listener (VCM v2)

Self-contained folder: run `vcm_pi.py`, speak a command, get the recognized
words, the classified command, and latency metrics printed for every
utterance.

## Files

| File | What it is | Size |
|---|---|---|
| `vcm_pi.py` | the listener (mic + VAD + inference + metrics) | 22 KB |
| `encoder_int8.onnx` | Whisper base.en **encoder** (fine-tuned, int8) | ~145 MB |
| `decoder_int8.onnx` | Whisper base.en **decoder + LM head** (int8) | ~145 MB |
| `encoder.onnx` / `decoder.onnx` | same, fp32 (fallback if int8 misbehaves) | ~290 MB each |
| `student_int8.onnx` | **distilled ~2.7M-param encoder** (mel → 512-d) | ~3 MB |
| `head_int8.onnx` | linear 32-way command head (512-d → logits) | ~16 KB |
| `classes.json` | head's label order (31 commands + REJECT) | 1 KB |
| `tokenizer/` | Whisper tokenizer + feature extractor (mel) | 3.9 MB |
| `requirements.txt` | deps | — |

Two backends, one script:

* `--model full` (default) — the production model: Whisper base.en
  fine-tuned on the ME2 domain. Greedy decode → transcript → TF-IDF+LogReg
  stage-2 classifier. **85.4% command / 86.0% intent** on the 171-clip
  held-out set (`test_data/additional_test_data`, one new speaker).
  Needs `classifier.pkl` from `vcm-v2/archive/ctc_v8/artifacts/` (already in
  the repo).
* `--model student` — the distilled student: mel → 512-d embedding → linear
  head → command. **No transcript, no tokenizer, no sklearn** — just two
  tiny ONNX graphs (~3 MB total). Trained by distilling the frozen Whisper
  encoder (`backbone/scripts/distill_student.py`). Accuracy on the held-out
  set: see `reports/test_student.json` (generated by `--test`).

## Install (on the Pi)

```bash
pip install -r requirements.txt
# mic input (usually works out of the box; for USB mics check `arecord -l`)
```

## Run

```bash
python vcm_pi.py                     # live mic, full model
python vcm_pi.py --model student     # live mic, distilled student
python vcm_pi.py --test              # run the 171-clip test set, print metrics
python vcm_pi.py --file clip.wav     # one file
```

## Per-utterance output (live mode)

```
[14:32:07] ── utterance #3 (2.41 s audio) ─────────────────
  transcript : 'turn on the lights'
  command    : LIGHT_ON  (prob 0.97)   intent: lights_switch
  mel 3.1 | enc 48.2 | dec 312.0 (21 steps) | classify 1.2 | ASR 363 ms | E2E 1190 ms
  3 utterances | ASR avg 341 ms p50 363 p95 380 | E2E avg 1102 ms ...
```

`--test` additionally reports command/intent accuracy, WER (mean/median),
ASR and E2E latency p50/p95, and writes `reports/test_<model>.json`.

## Latency expectations (Pi 5, CPU, int8)

* student: ~30–80 ms per utterance (no decode loop)
* full: ~1.5–4 s per utterance (64-step greedy decode on CPU)

If full-model latency is too high, the student backend is the trade-off:
a few points of accuracy for ~10–50× lower latency and a 3 MB footprint.
